# V2: a group-readable Chromium policy file — PASS

Machine: omarky-air (2019 MacBook Air, T2), Omarchy 4.0.2, Chromium 151.0.7922.173 (Arch).
Date: 2026-09-02. Script: `test/phase1/v2-policy-group.sh` (creates test user `kid-test`).

## What was tested

A policy file at `/etc/chromium/policies/managed/omarchy-kids-v2test.json`, owner `root`, group
`omarchy-kids`, mode `0640`, containing `URLBlocklist: ["*"]` plus an allowlist for `chrome://`.
The parent account is not in the group; `kid-test` is. Both load `http://127.0.0.1:8123/` (a port
with nothing listening) in headless Chromium.

## Result

| Account | Can read the file | What the page shows | Chromium log |
| --- | --- | --- | --- |
| parent (not in group) | no | `ERR_CONNECTION_REFUSED`, the ordinary error page | `WARNING: … config_dir_policy_loader.cc:138 Failed to read configuration file … Can't read file.` |
| kid-test (in group) | yes | "Your organization has blocked this page" | (policy applied) |

The parent's browser loads **no** policy from the unreadable file, logs one warning, and behaves
exactly as it did before. The kid's browser is locked. This matches the source read in
`components/policy/core/common/config_dir_policy_loader.cc`: an unreadable file is skipped with
`continue`.

## Notes

- `chrome://policy` cannot be used as a probe under `--dump-dom`: its table is filled in by
  JavaScript after the DOM dump, even with a virtual-time budget. A functional probe (a blocked
  URL) is the reliable check.
- The policy-block page carries no `ERR_` code in its DOM; it says the organization blocked it.
- Run as another user with `sudo -H -u <user>`; without `-H`, Chromium inherits the parent's
  `$HOME` and misbehaves.
- The managed policy directory watches for changes, so edits apply to running browsers.

## Consequence for the spec

R-WEB-1 stands as written. The fail-open risk on the kid's side (a kid removed from the group
would get an unlocked browser) is covered by R-WEB-4, the launcher's readability check, and by
`omarchy-kids-check` at login.
