Machine: the test VM on omarky-air (`docs/vm.md`), Omarchy 4.0.2, encrypted, kernel 7.1.9, mkinitcpio
41, limine-mkinitcpio-hook 1.37. Date: 2026-09-02. Code: `initcpio/hooks/omarchy-kids-unlock`,
`initcpio/omarchy-kids-open`, `etc/mkinitcpio.conf.d/omarchy_kids.conf`, `bin/omarchy-kids-boot-login`
and its two units (#36). Deployed with `scripts/deploy-boot-hook.sh`.

- Slots after V4: 0 = owner (`omarchy`), 1 = `kidpass-ada`, 4 = `kidpass-ben2`.
- `/etc/omarchy-kids/luks-slots`: `0=kid-vm:omarchy.desktop`, `1=kid-ada:omarchy.desktop`.
- A second account `kid-ada` (plain `useradd -m`, password set).
- `HOOKS` as mkinitcpio sees them after our conf.d file: `… block omarchy-kids-unlock encrypt …`.
  The file is named `omarchy_kids.conf` on purpose: conf.d files source in byte order and Omarchy's
  `omarchy_hooks.conf` assigns `HOOKS`, so ours must sort after it.

## Things learned the hard way

- Omarchy's session file lives at `/usr/local/share/wayland-sessions/omarchy.desktop`, not under
  `/usr/share`; SDDM scans both. `Session=` values need the `.desktop` suffix (boot-login adds it).
- SDDM never attempts autologin when the merged `[Autologin] User=` is empty, and logs nothing
  about it; with a wrong session name it would fall back to the greeter the same silent way.
- `mkinitcpio -P` on Omarchy prints `ERROR: No presets found in /etc/mkinitcpio.d` and then
  builds the UKI anyway through the limine hook. Verify the image, not the exit text:
  `objcopy -O binary --only-section=.initrd <uki> ir.img && lsinitcpio ir.img | grep omarchy-kids`.
- The earlier stock-Omarchy behavior (V4): a kid's password unlocked the disk and the **owner**
  was autologged. With the hook and the boot-login unit in place, that no longer happens.

## Fail-safe (I-9) — PASS

The runtime hook was replaced with one that prints a marker and returns 1, the image was rebuilt,
and the marker was confirmed inside the initramfs (`lsinitcpio -x`, 1 hit) before rebooting.

| Check | Result |
| --- | --- |
| Boot with the owner's password | the stock `encrypt` prompt appeared and worked; SSH reachable |
| `/run/omarchy-kids/boot-slot` | absent |
| Graphical session on seat0 | only the SDDM greeter: the portal, no autologin |
| Restore the good hook and rebuild | marker gone, hook present in the image |

So a broken hook costs nothing but the convenience: the machine boots, and because no slot was
recorded the boot-login unit disables Omarchy's owner autologin for that boot, which is what keeps
a kid who unlocked the disk off the parent's desktop. The unit runs unconditionally for exactly
this reason (review fix on #36).
